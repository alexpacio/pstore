Prompt Store

A native GUI that makes prompt authoring a first-class activity — versioned markdown files, inline LLM hints, automatic model selection, and one-keystroke handoff to coding agents.

Rust + egui Native GUI Cross-platform MIT License

Why pstore?

Writing a good prompt for a coding agent is iterative. Today that work happens in a scratch buffer with no history, no help while writing, and no idea which of the installed agents/models is the right (cheapest, fastest-adequate) target.

pstore solves this by treating prompt authoring as a first-class workflow:

  • Versioned markdown files in your working folder — plain .md files you can git, grep, and edit anywhere
  • Inline LLM hints while typing — context-aware suggestions without leaving the editor
  • Automatic difficulty/capability scoring — picks the cheapest adequate model for the task
  • One-click PII masking — replace names, addresses and identifiers with placeholders before the prompt reaches an agent
  • One-keystroke handoff — send the prompt to a real agent session instantly

Features

📝

Versioned Prompts

Every save creates a snapshot in .pstore/versions/. Full history, diffs, and one-click restore — all as plain markdown files.

💡

Inline Hints

Select text and get LLM-powered suggestions: clarify, expand, add constraints, fix ambiguity. Inserted directly at the cursor.

🎯

Smart Model Routing

A capability classifier scores your prompt across 6 dimensions and a difficulty classifier rates how hard it is. Picks the cheapest model that meets the threshold — no more overpaying for Opus when you need Haiku.

🛡️

PII Sanitizer

Finds names, addresses, IBANs, tax codes and card numbers and swaps them for stable placeholders like [FULLNAME_1]. Structured identifiers are confirmed by their checksum, so code and version numbers are left alone. You see the diff before anything changes.

🔒

Models Run Locally

Every model pstore runs itself is a small encoder loaded in-process via Candle, on Metal, CUDA or CPU. Download them once from the Models window — with the size stated up front and progress shown — and nothing about your prompt leaves the machine again.

⚡

One-Key Handoff

Press Enter (or your binding) to launch the selected agent with the prompt. Supports Claude Code, Codex, Gemini, Cursor, and 10+ others.

🔧

The Whole Field, Not a Verdict

Every (agent, model, effort) combination is scored and shown with its speed and its rationale, so you can disagree with the pick. Token price is displayed alongside — and deliberately kept out of the score.

💳

Metered Models Stay Out of the Way

Claude Fable 5 is the one model billed per token rather than covered by the subscription. It is scored like everything else, but only picked automatically when it fits better than every included model by a clear margin — never by a tie or a rounding accident. Pin it from the target list when you do want it.

📁

Plain Files Everywhere

Prompts are .md files in your project. Sidecar state in .pstore/. No lock-in, no database, works with git and any editor.

Installation

cargo install --git https://github.com/alexpacio/pstore

Requires Rust 1.78+. Installs the pstore binary to ~/.cargo/bin/.

Download the latest release for your platform:

# Linux (x86_64)
# macOS (Apple Silicon)
# Windows (x86_64)
git clone https://github.com/alexpacio/pstore
cd pstore && cargo build --release
./target/release/pstore

Quick Start

# In your project directory pstore # Or specify a prompt directory pstore ~/my-prompts

This opens the pstore window with a sidebar listing all .md files in the directory. Create a new prompt, start typing, and use the features:

  • Ctrl+S — Save (creates a version snapshot)
  • Ctrl+R — Score every installed model and effort level
  • Ctrl+Enter — Request a hint about the selection or question
  • Ctrl+Z / Ctrl+Shift+Z — Undo / Redo
  • Ctrl+M — Toggle preview mode

Action bar: Score models · Shrink · Sanitize · Send → · Hint… · Models…

Configuration

Settings are stored in .pstore/config.json in your prompt directory:

{ "hint_score_tolerance": 8.0, // points of fit a hint may trade for speed "preview": false, // start in preview mode "sidebar_width": 260, // sidebar width in points "pinned_agent": null, // override auto-selected agent "allow_model_download": true // may pstore fetch weights from Hugging Face at all }

The Local Models

pstore uses three checkpoints and runs all of them in its own process, on your machine. None is contacted at inference time; the only network traffic is the one-off weight download you start from Models…, which states each file's size up front and shows its progress as it arrives.

  • regolo/brick-modernbert-capability-classifier — multi-label capability vector over the six routing dimensions (ModernBERT, sigmoid head). 795 MB.
  • nvidia/prompt-task-and-complexity-classifier — task type plus six complexity dimensions, reweighted for coding prompts into easy/medium/hard (DeBERTa-v3). 744 MB.
  • rizzoaiacademy/rizzo-pii-0.3B — BIO token classification over 22 kinds of personal data, from rizzo-pii (mmBERT). 1.26 GB.

Weights land in the shared Hugging Face cache, so other tools reuse them. Until a checkpoint is downloaded the feature that needs it degrades visibly: routing falls back to a built-in surface-feature estimate and says so in the status bar; sanitizing falls back to checksum-validated patterns (IBAN mod-97, Luhn, codice fiscale, partita IVA, email) and says so in the review window.

Brick's own difficulty checkpoints are LoRAs on Qwen3.5-0.8B — a hybrid attention/SSM architecture candle-transformers has no implementation for — so they could never load, and difficulty quietly fell back to the heuristic. The NVIDIA classifier replaces that half. Its published complexity score is weighted for general-purpose prompts, where creativity and domain_knowledge turn out to be near-constant across coding prompts; pstore reweights the model's own dimensions towards the ones that discriminate here, and the weights, thresholds and calibration set are all in src/router/difficulty.rs.

The hint and shrink features are different in kind: they deliberately drive your installed coding agent, which is the point of the tool. Those are the only paths where prompt text leaves the process, they are always an explicit action, and the sanitizer exists to run before them.

Architecture

Project Structure

pstore/ ├── src/ │ ├── main.rs # Application entry point │ ├── config.rs # Runtime config & persisted preferences │ ├── models.rs # Local checkpoint catalogue + download/load status board │ ├── pii/ │ │ ├── mod.rs # Findings, placeholder plan, BIO decoding │ │ ├── detect.rs # Checksum-validated identifiers (IBAN, Luhn, CF, P.IVA) │ │ └── model.rs # rizzo-pii token classifier on Candle │ ├── router/ │ │ ├── capability.rs # Brick ModernBERT capability classifier │ │ ├── difficulty.rs # NVIDIA DeBERTa task/complexity classifier │ │ ├── heuristic.rs # Surface-feature fallback for both signals │ │ ├── hub.rs # Hugging Face cache probe / download with progress │ │ └── scoring.rs # (agent, model, effort) ranking │ ├── store/ │ │ ├── mod.rs # PromptStore: list/create/read/write/rename/delete │ │ └── version.rs # Version history (snapshots, diffs, index) │ ├── editor/ │ │ ├── mod.rs # Buffer: text, selection, dirty tracking │ │ └── undo.rs # Snapshot-based undo/redo with coalescing │ └── agents/ │ └── registry.rs # Static agent/model specs & capability vectors ├── Cargo.toml └── README.md

Key Design Decisions

  • Plain files: Prompts are .md files. Sidecar state in .pstore/. No database, no lock-in.
  • Snapshot-based undo: Coalesces typing into word/line granules. Programmatic edits (shrink, hint, restore) are single atomic steps.
  • Static agent registry: All agent CLIs and model specs in one file. Adapting to upstream flag changes is a one-line edit.
  • Capability routing: Uses a 6-dimension skill vector per model. Quality/cost tradeoff controlled by a single r parameter (Brick-style objective).
  • Local inference only: Every model pstore runs itself is loaded in-process via Candle. Weights are downloaded on request, never at startup, and the app degrades visibly rather than silently when one is missing.
  • Nothing applied unreviewed: Shrink and sanitize both propose a diff. Accepting is one undo step, and the previous text is already in version history.
  • egui/eframe: Native GUI, no Electron. Small binary, fast startup, works on Linux/macOS/Windows.
